# JOCAM

「我和叫叫合拍」手机端相机 Demo，正式路径为 `https://mikeywa.site/jocam/`。

## 功能

- 整体 UI 使用温暖黄色作为主色，加载、按钮、状态和二维码保持同一视觉语言。
- 桌面浏览器左侧使用无边框全屏相机舞台，叫叫按窗口左边缘对齐并限制在相机可视安全区内；右侧使用独立的浅黄色侧栏和较小的白底二维码，不会遮住叫叫，标题为「扫码和叫叫合影」。
- 手机和 Pad 会自动进入沉浸式布局，隐藏二维码与辅助提示，让竖屏和横屏取景框尽可能占满可用空间。
- 摄像头画面作为 Rive 透明区域的背景。
- 打开前置摄像头并取得权限后，会优先选择设备名称中明确标注的「前置超广角 / Ultra Wide」镜头，其次选择前置广角镜头；同时将硬件缩放设为该镜头允许的最小值。浏览器未公开镜头名称或缩放能力时会无感保留系统默认前摄，不影响进入相机；后置镜头不会参与这次自动选择。
- 进入相机前就会加载并以 0.25 倍速播放同一个叫叫 Rive 文件，前方覆盖深色遮罩和高斯模糊；开场不再显示左上角 JOCAM 标识。进入相机后，叫叫以 0.8 倍速播放。
- 「进入相机」按钮会在同一次用户点击中播放第一句引导语并取得浏览器声音播放授权；后续表情只以 34% 概率、至少间隔 7 秒偶尔说一句。引导语使用 Fish Audio 公开的「小男孩 2」普通话男童音色与 S1 生成，8 段静态 MP3 均已测量时长，最长的表情引导为 2.482 秒，短于当前最短表情在 0.8 倍速下的 4.5 秒。
- 语音播放期间额外叠加 `Talking_Normal`，只驱动嘴型；语音暂停或结束会单独停止嘴型，不会打断正在播放的表情。所有表情切换前都会先应用 `Ipad` 时间轴的最终定位作为统一基准，避免 `Frighten` 等动作把整只叫叫带回画面中间。
- 进入相机时同时请求麦克风权限，语音以 16kHz/16bit/单声道 PCM 实时发往腾讯云上的专用 WebSocket 桥接，再由服务端连接火山引擎豆包流式语音识别。原始音频不落盘、不进入网页构建产物。麦克风被拒绝时相机仍可正常使用。
- 每次语音识别请求都会带上品牌热词上下文：除了「叫叫、绿豆、粉豆、猪小弟、铃铛、思维、阅读、萌萌星球、豆荚号」，还从《叫叫-IP设定资料》筛选了叫叫小分队的角色与地点、豆豆家族、阅读线和识字线等稳定专名。服务端还会对「笑笑→叫叫」等少量高把握同音误识别做即时校正。调试指标只记录校正次数和命中的词对，不记录用户完整话语或原始音频。
- MediaPipe Face Landmarker 只在本机跟踪用户嘴部和双眼安全线，识别到的文字会以白色扁椭圆气泡显示，最多两行、黑色粗体；气泡宽度按实际文字测量结果收紧，底部使用小三角尾巴并自动上移避开眼睛。实时文字使用 Calligraph 的平滑逐字入场，照片和录像仍会把同一段文字直接画入合成画布。
- MediaPipe Gesture Recognizer 也只在设备本机分析手部关键点：点赞连续稳定 3 帧后，当前角色会同步播放 `TalkingEmotion_Praise`；比耶会播放 `TalkingEmotion_Happy`；OK 和单手指尖比心会根据拇指、食指及另外三根手指的姿态区分，分别播放 `TalkingEmotion_Sure` / `TalkingEmotion_Happy`，并用 Fish Audio「小男孩 2」说「我看到你比 OK 啦」或「我看到你比心啦」。点赞、比耶和 OK 还会触发 2.6 秒彩色跑马灯实体描边：直接从人像蒙版向外扩边再扣掉本体，沿用「儿童反应视频」的 iOS Safari 兼容方案，并进入实时预览、照片和录像。同一姿势需先松开才能再次触发，并有 4.8 秒全局冷却，避免手部晃动时重复回应。
- 语音终稿中出现“叫叫比个赞”、“做个惊讶表情”等动作指令时，服务端使用火山方舟 Responses API 的流式 Function Calling，仅能返回 `praise` / `surprised` / `think` / `happy` / `frighten` / `curious` 六个白名单动作。网页再将动作映射到固定 Rive 时间轴，不接受模型自由生成的时间轴名。
- 六个指令动作都有 Fish Audio “小男孩 2”音色的本地预置反馈，时长为 2.011–3.004 秒。反馈播放时会暂停上传麦克风 PCM，避免叫叫把自己的声音重复识别成新指令。
- 桌面扫码侧栏延迟 0.5 秒后从右侧以 0.8 秒临界阻尼弹簧曲线滑入，全程不越过终点、不回弹；系统启用减少动态效果时直接静态显示。
- 叫叫默认位于人像前面，MediaPipe 人像分割层可随时切换到叫叫前面，图层按钮用「人在前」和「鸡在前」直接显示当前状态，拍照和录像都使用当前图层顺序。
- 人像蒙版使用硬阈值切边，仅保留约 5px 的羽化过渡，优先保证抠像轮廓锐利。
- 叫叫按 Rive 画布左下角稳定锚定，在原显示尺寸上放大 1.25 倍并稍微越过取景框左边，让左手只露出更少的部分，形成扶着相机的感觉；横屏时额外放大 1.35 倍，是上一版横屏大小的 90%。每次切换动作都会自动检测透明边界，但裁切位置只会向左补偿右侧内容，并使用 `Ipad` 定位基准避免 `Frighten` 等时间轴重新往中间移动；以 `Start_Dial` 开始，当前时间轴完整播完后才从筛选后的 `TalkingEmotion` 时间轴中随机切换，单击角色统一播放 `TalkingEmotion_Praise`，也会等该时间轴播完再继续随机播放。
- 进入相机后才会以低优先级在后台加载绿豆，不计入首屏进度。连续点击角色三次会在叫叫与绿豆之间切换：当前角色向屏幕左侧退场，新角色再从屏幕左边缘入场；两个文件共用同一套时间轴、嘴型和拍摄合成逻辑。
- Rive 优先使用 WebGL2 运行时及配套 WASM 渲染叫叫和绿豆，保留绿豆资源中的羽化表现。Safari、iOS WebKit、没有 WebGL2 的设备或实际 WebGL2 初始化失败的环境会自动切到独立的 Rive Canvas 运行时与 Canvas WASM；角色切换复用同一个 Rive 实例，避免重复释放纹理。
- 每次进入页面时随机生成 1-520 的阅读天数，平时和录像期间保持不变；点击顶部字幕可切换两种文案并重新随机数值。
- 两种字幕都在「第」字前换行，第二行整体放大 1.25 倍，并相对取景框向下移动 2%；第一种字幕使用黄色数字，第二种「坚持连续学习叫叫阅读」字幕使用红色大号数字和加粗白色描边，相机实时预览中的红色数字不加投影。
- 支持竖屏 `720×1280` 和横屏 `1280×720` 成片，并跟随系统屏幕方向自动切换，不提供额外的旋转按钮。
- 移动设备竖屏时，成片取景框避开刘海与系统安全区；人像图层和前后摄像头分别在快门两侧的剩余空间内居中。横屏时三枚按钮在右侧纯黑操作区竖排，上下功能按钮也分别在快门两侧的剩余空间内居中，所有工具都不会进入照片或录像。
- 轻点快门拍照，长按快门录像，最长 15 秒。拍照会锁定按下快门瞬间的叫叫时间轴，向前推进 4 帧后同步固化完整合成画面，避免异步编码期间回到默认表情。
- 点赞、比耶、OK 的手势反馈触发后，会等待 360ms 让角色表情和彩色跑马灯进入画面，再自动拍下一张照片；用户通过语音让叫叫执行预置动作时，也会在反馈语音和嘴型播放期间自动拍照。自动拍照遵守 1.2 秒防重复间隔，录像、作品列表或成片预览打开时不会抢拍。
- 拍摄操作区调整为「作品入口—快门—菜单」：竖屏时作品缩略图位于快门左侧、菜单位于右侧；横屏时菜单在快门上方、作品缩略图位于下方。原来的人物层级与前后摄切换均收进菜单内。
- 拍好的照片和短视频不会再强制打断相机，而是进入本机作品列表；最近一条会显示在快门旁的缩略图中。作品通过 IndexedDB 保存在当前浏览器，刷新后仍可打开，最多保留最近 30 条且不会上传服务器；浏览器存储不可用时仍保留本次打开期间的作品。
- 浏览器能收到实体音量键事件时，音量加、音量减均可触发拍照；iPhone Safari 通常不向网页暴露该事件，屏幕快门始终可用。
- 照片预览缩放为原来的 0.8 倍，为手机刘海和安全区留出空间；放大的关闭按钮以照片或视频右上角为中心，部分覆盖成片内容。
- 成片自带「我和叫叫一起阅读的第 xx 天」字幕。
- 叫叫、Rive 运行时、人像与手势模型均为同源静态资源，并显示真实首屏加载进度；绿豆只在进入相机后后台加载。
- 相机帧仅在用户设备上合成，不上传。

## 本地开发

```bash
npm install
npm run dev
```

## 构建

```bash
npm run build
```

构建产物输出到仓库根目录的 `jocam/`。正式构建默认从 `https://rive.mikeywa.site/jocam/` 直连加载大体积资源，让最终页面仍保持在 `https://mikeywa.site/jocam/`，也不会把叫叫和人像模型绕回旧服务器。可以用 `JOCAM_ASSET_BASE` 覆盖该资源基地址。

## 语音服务

`server/` 是只运行在腾讯云的 Node.js 桥接，不会被 Vite 打包到浏览器。复制 `server/voice.env.example` 到服务器 `/etc/jocam/voice.env`，填入豆包语音 API Key（或旧版 App ID + Access Token）和火山方舟 API Key。环境文件权限必须为 `0600`。

```bash
npm run voice-server
npm run test:voice
```

正式环境由 `jocam-voice.service` 管理，Nginx 只将 `/jocam/api/voice` 的 WebSocket 升级转发到 `127.0.0.1:8787`。服务端限制来源域名、单 IP 并发数和 5 分钟会话时长，不记录原始音频或识别文字。

叫叫 Rive 源文件来自 `https://rive.mikeywa.site/mBK`，入库文件的 SHA-256 为 `203a6f992698be770a4b49fb42f2632f095cef22490fa426bf933ed37c929233`。绿豆 Rive 源文件来自 `https://rive.mikeywa.site/1sf`，入库文件的 SHA-256 为 `f67a7057c8f465ed4c227770d9b0fd9b21cc405ad94af70837f7bb83d0f63b6a`。

手势模型使用 MediaPipe 官方 `gesture_recognizer.task`，入库文件的 SHA-256 为 `97952348cf6a6a4915c2ea1496b4b37ebabc50cbbf80571435643c455f2b0482`。OK 与比心反馈音频时长分别为 1.933 秒和 1.646 秒。

`deploy/nginx-rive-jocam.conf` 让大体积资源从腾讯云源站直连加载；`deploy/nginx-mikeywa-jocam.conf` 只负责在主站保留 `/jocam/` 入口。两份片段分别由 `rive.mikeywa.site` 和 `mikeywa.site` 的 HTTPS server 块引用。
